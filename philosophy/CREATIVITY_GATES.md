# Creativity Gates

> **Principle**: When territory is uncharted, creativity gates verify the path is properly built.
> Creativity gates ensure we're not just building, but building well—creating paths that enable future justice.

## Gate 0: Territory Gate (Pre-check)

### Core Question
**Is this uncharted territory?**

This gate determines whether creativity mode is needed.

### Gate Criteria

```markdown
## Territory Gate Checklist

- [ ] No existing structure for this type of solution
- [ ] No established patterns to follow
- [ ] No rightful place exists in current codebase
- [ ] Justice cannot be achieved with existing structure

**Territory Status**: [Charted / Uncharted]

If Charted → Justice mode (skip creativity gates)
If Uncharted → Creativity mode (continue with creativity gates)
```

### Pass/Fail

| Condition | Result |
|-----------|--------|
| Territory is charted | **JUSTICE MODE** - Use existing structure |
| Territory is uncharted | **CREATIVITY MODE** - Continue with gates |

## Gate 1: Pioneering Gate

### Core Question
**Is this genuinely new ground?**

Ensures we're not reinventing what already exists.

### Gate Criteria

```markdown
## Pioneering Gate Checklist

- [ ] Genuinely new for this codebase
- [ ] No existing precedent here
- [ ] Not reinventing existing structure
- [ ] Truly extending boundaries

**Pioneering Status**: [Genuine / Reinventing / Uncertain]
```

### Pass/Fail

| Condition | Result |
|-----------|--------|
| Genuinely new territory | **PASS** |
| First of its kind here | **PASS** |
| Similar exists elsewhere in codebase | **FAIL** - Find and use existing |
| Reinventing the wheel | **FAIL** - Use existing patterns |

### When Gate Fails

```
Not actually pioneering—similar exists.

Action:
1. Search codebase for existing patterns
2. Look for similar structure
3. Use or extend existing instead
4. Only pioneer if truly needed
```

## Gate 2: Path-Building Gate

### Core Question
**Is the structure well-constructed?**

Ensures the path we build is followable and maintainable.

### Gate Criteria

```markdown
## Path-Building Gate Checklist

- [ ] Structure is clear and understandable
- [ ] Others could follow and extend this path
- [ ] Path is sustainable long-term
- [ ] Structure is robust, not fragile
- [ ] Path leads somewhere valuable

**Path-Building Status**: [Well-built / Fragile / Unclear / Dead-end]
```

### Pass/Fail

| Condition | Result |
|-----------|--------|
| Well-constructed, followable | **PASS** |
| Sustainable and robust | **PASS** |
| Fragile or unclear | **FAIL** - Strengthen structure |
| Dead-end path | **FAIL** - Reconsider direction |

### When Gate Fails

```
Path is not well-constructed.

Action:
1. Clarify the structure
2. Make patterns explicit
3. Ensure maintainability
4. Build for others to follow
```

|-----------|--------|

## Claude-Specific Enhancement: Proof Gate

> **Principle**: Claude may build where structure already exists.
> Proof Gate requires demonstrating exhaustive search before declaring territory uncharted.

### Core Question
**Can I prove this territory is uncharted through exhaustive search?**

### Why This Gate Exists

Claude tends to:
- Declare territory "uncharted" without thorough search
- Miss existing patterns that could be extended
- Build new structure when modification would suffice
- Not know what it doesn't know about a codebase

Proof Gate ensures **prove before pioneer**.

### Gate Criteria

```markdown
## Proof Gate Checklist

Before declaring territory uncharted:

- [ ] Searched multiple relevant terms (Grep)
- [ ] Searched multiple file patterns (Glob)
- [ ] Documented what searches returned nothing
- [ ] Identified "near misses" (close but not quite)
- [ ] Can articulate why existing can't be extended
- [ ] Burden of proof met for building new

**Proof Status**: [Proven uncharted / Insufficiently searched / Actually charted]
```

### Proof Protocol

```markdown
## Exhaustive-Search-Document Protocol

BEFORE building new structure:

1. **MULTI-TERM SEARCH**
   └─ Grep: [term1], [term2], [synonym1], [related]
   └─ Document: [search results or "0 results"]

2. **MULTI-PATTERN SEARCH**
   └─ Glob: **/*[pattern1]*, **/*[pattern2]*
   └─ Document: [files found or "0 files"]

3. **NEAR-MISS ANALYSIS**
   └─ What's close but doesn't fit?
   └─ Document: "[X] is close but doesn't work because..."

4. **EXTENSION ANALYSIS**
   └─ Can existing patterns be extended?
   └─ Document: "Cannot extend [X] because..."

5. **BURDEN OF PROOF**
   └─ Prove building new is necessary
   └─ Document: "Must build new because..."
```

### Pass/Fail

| Condition | Result |
|-----------|--------|
| Multiple searches documented as empty | **PASS** |
| Near-misses identified and rejected with reason | **PASS** |
| Extension impossibility explained | **PASS** |
| Single search then "uncharted" | **FAIL** - Search more |
| No near-miss analysis | **FAIL** - Analyze close options |
| "Nothing exists" without search proof | **FAIL** - Show searches |

### When Gate Fails

```
Territory status not proven.

Action:
1. SEARCH with multiple terms
2. SEARCH with multiple patterns
3. DOCUMENT all search attempts
4. IDENTIFY near-misses
5. EXPLAIN why extension doesn't work
6. THEN declare uncharted (if still true)

Never: "There's no existing pattern for this"
Always: "Searched for existing patterns:
  - 'authentication': 15 results, but all JWT-based
  - 'OAuth': 0 results
  - 'social login': 0 results
  - Near miss: AuthService could extend but lacks OAuth flow
  - Cannot extend because: Would require breaking changes
  → Territory uncharted for OAuth integration"
```

### Proof Documentation Template

```markdown
## Uncharted Territory Proof: [What You're Building]

### Search Attempts

| Search Term | Results | Notes |
|-------------|---------|-------|
| "[term1]" | N files | [what was found] |
| "[term2]" | 0 files | - |
| "[synonym]" | 0 files | - |

### Near-Miss Analysis

| Candidate | Why Close | Why Doesn't Work |
|-----------|-----------|------------------|
| [existing1] | [similarity] | [gap or limitation] |
| [existing2] | [similarity] | [gap or limitation] |

### Extension Analysis

- **Could extend [X]?** No, because [reason]
- **Could extend [Y]?** No, because [reason]

### Conclusion

Territory is uncharted because:
1. No existing implementation found [search evidence]
2. Near-misses cannot be adapted [reasons]
3. Extension of existing would require [breaking changes / doesn't fit]

Proceeding with new structure.
```

### Examples

**Bad (No Proof)**:
```
We need a new caching system. Let me build one.
```

**Good (With Proof)**:
```
Searched for existing caching:
- "cache": Found src/utils/cache.ts (simple in-memory, no TTL)
- "redis": 0 results
- "ttl": 0 results
- "expir": 0 results

Near-miss analysis:
- src/utils/cache.ts is close but:
  - No TTL support
  - No size limits
  - Would need significant rewrite

Extension analysis:
- Could extend cache.ts? No - lacks fundamental TTL architecture
- Adding TTL would break existing callers

Conclusion: Territory uncharted for TTL-based caching.
Building new: src/services/CacheService.ts
```

### Burden of Proof Levels

| Scope | Required Proof |
|-------|----------------|
| New utility function | 2+ search terms, check utils/ |
| New service | 5+ search terms, check services/, check for similar patterns |
| New architectural pattern | Exhaustive search, near-miss analysis, extension impossibility |
| New domain/module | All of above + architecture review |
