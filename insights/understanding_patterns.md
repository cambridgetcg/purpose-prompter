## Understanding Transfer Strategies

### By Understanding Dimension

#### Enabling Conceptual Understanding
**Goal**: Help user grasp core ideas and concepts

**Effective strategies**:
- Define the concept clearly before elaborating
- Contrast with similar but different concepts
- Use analogies to familiar things
- Show the "essence" before the details

**Common failures**:
- Jumping into details without establishing concept
- Using jargon without translation
- Assuming familiarity that doesn't exist

---

#### Enabling Structural Understanding
**Goal**: Help user see how parts relate to form wholes

**Effective strategies**:
- Start with the big picture, then zoom in
- Show relationships explicitly
- Use visual metaphors (layers, trees, flows)
- Make dependencies clear

**Common failures**:
- Listing parts without showing relationships
- Missing the "glue" that holds pieces together
- No organizing framework

---

#### Enabling Causal Understanding
**Goal**: Help user know why things work the way they do

**Effective strategies**:
- Always explain WHY, not just WHAT
- Show cause-and-effect chains
- Explain mechanisms, not just outcomes
- Connect back to first principles

**Common failures**:
- Stating facts without reasoning
- Leaving causation implicit
- "Just do this" without explanation

---

#### Enabling Procedural Understanding
**Goal**: Help user know how to do something

**Effective strategies**:
- Break down into clear steps
- Explain why each step matters
- Show what happens if steps are skipped
- Provide concrete examples

**Common failures**:
- Assuming knowledge of prerequisites
- Missing steps that seem "obvious"
- No error recovery guidance

---

#### Enabling Contextual Understanding
**Goal**: Help user see how it fits in larger picture

**Effective strategies**:
- Show where this fits in the ecosystem
- Explain when this applies (and doesn't)
- Connect to user's specific situation
- Show alternatives and why this vs. them

**Common failures**:
- Presenting without context
- Assuming context is shared
- Not connecting to user's situation

---

#### Enabling Consequential Understanding
**Goal**: Help user know what follows from something

**Effective strategies**:
- Explicitly state implications
- Discuss trade-offs
- Show second-order effects
- Help user anticipate outcomes

**Common failures**:
- Not mentioning trade-offs
- Ignoring negative consequences
- Overpromising outcomes

## Understanding by Content Type

### Technical Explanations

**What works**:
| Strategy | Why It Works |
|----------|--------------|
| Analogy first | Anchors new concept to familiar |
| Build-up approach | Layer complexity gradually |
| Concrete then abstract | Ground theory in examples |

**What fails**:
| Anti-pattern | Why It Fails |
|--------------|--------------|
| Jargon without translation | Words without meaning |
| Abstract without concrete | Nothing to hold onto |
| Too much at once | Overwhelm blocks understanding |

---

### Recommendations

**What works**:
| Strategy | Why It Works |
|----------|--------------|
| Reasoning provided | User can evaluate and adapt |
| Trade-offs explicit | User can make informed choice |
| Context-specific | Recommendation fits situation |

**What fails**:
| Anti-pattern | Why It Fails |
|--------------|--------------|
| "Just do X" | No understanding, just compliance |
| One-size-fits-all | Ignores user's context |
| No alternatives discussed | Can't evaluate choice |

---

### Architecture/Design

**What works**:
| Strategy | Why It Works |
|----------|--------------|
| Mental model first | Framework for details |
| Decisions explained | User can evolve design |
| Components and connections | Shows structure |

**What fails**:
| Anti-pattern | Why It Fails |
|--------------|--------------|
| Just the diagram | No understanding of why |
| Components without relationships | No mental model |
| Missing decision rationale | Can't maintain or evolve |

---

### Code/Implementation

**What works**:
| Strategy | Why It Works |
|----------|--------------|
| Intent explained | User knows what code does |
| Design choices noted | User can modify appropriately |
| Patterns identified | User sees transferable concepts |

**What fails**:
| Anti-pattern | Why It Fails |
|--------------|--------------|
| Code without explanation | User can't maintain |
| Magic solutions | User can't debug or extend |
| No context | User doesn't know when to use |

## Understanding Gap Patterns

### Common Gate Failures

| Gate | Common Failure | Root Cause | Prevention |
|------|----------------|------------|------------|
| Truth | Overconfidence | Assuming certainty | Calibrate to evidence |
| Model | Info dump | Eager to share knowledge | Structure first |
| Why | Implicit reasoning | Assumes user will infer | Make explicit |
| Connection | Floating knowledge | Focused on content not user | Anchor to known |
| Application | Abstract only | Theory over practice | Add examples |
| Boundary | Overselling | Want to seem helpful | Add limitations |

### Understanding Blockers

| Blocker | Signs | Remedy |
|---------|-------|--------|
| **Jargon barrier** | User asking "what does X mean?" | Define or translate terms |
| **Cognitive overload** | User seems lost | Simplify, chunk information |
| **Missing prerequisite** | User can't follow reasoning | Back up, establish foundation |
| **Wrong mental model** | User's questions reveal misconception | Explicitly address misconception |
| **No anchor** | User can't relate to anything | Find familiar starting point |
