## Legacy Transformation Protocol

When old files contradict new understanding:

### Assessment

```markdown
## Legacy File Assessment

**File**: [filename]
**Created**: [when]
**Last Updated**: [when]

### Conflict Analysis
- What concepts conflict with current hierarchy?
- What valuable content should be preserved?
- What outdated content should be removed?

### Transformation Options
1. **Integrate**: Merge valuable content into appropriate current file
2. **Transform**: Update file to align with current hierarchy
3. **Archive**: Move to archive with note about supersession
4. **Remove**: Delete if no valuable content
```

### Transformation Decision

```
Legacy File
    │
    ▼
Contains valuable unique content?
    │
    ├── YES → Where does this content rightfully belong?
    │         │
    │         ├── Existing file → Integrate into that file
    │         └── No existing place → Create place (if justified)
    │
    └── NO → Is this causing confusion?
             │
             ├── YES → Remove or archive
             └── NO → Can leave for now
```

### When to Run Self-Application

- After adding new files to PP
- After making significant changes
- When something feels "off" about the framework
- Periodically as maintenance
- Before claiming PP is "complete"

### How to Run

```
1. Read SELF_APPLICATION.md (this file)
2. Run each self-check (Truth, Understanding, Beauty, Justice, Creativity)
3. Document gaps found
4. Apply PP to fix gaps
5. Verify fixes pass gates
6. Check coherence across files
7. Handle any legacy issues
8. Iterate until aligned
```
